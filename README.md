## 🌦️ 기상청 날씨 API 서비스 개선 프로젝트

### 개요

기상청 API 프로젝트를 아래 조건에 맞춰 개선한다.
확장성과 유지보수성이 뛰어난 형태로 서비스를 구성하는 것을 목표로 한다.

### 조건

**아래 연동되어 있는 두 API를 개선할 것.**
- [기상청 중기예보](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15059468)
- [기상청 단기예보](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15084084)

**아래 API 추가 연동 할 것**
- [기상청 특보](https://www.data.go.kr/data/15000415/openapi.do)

### 원칙

- 프로젝트는 정상적으로 빌드되고, 실행되어야함.
- 반환 타입을 data class로 매핑할 것.
- 각 모듈과 객체가 수행하는 행위와 책임을 명확히 분리할 것.
- 각 API 호출 시 로그를 남길 것.
  - **단, 로그를 남기는 코드가 Spring의 StereoType 으로 선언된 Bean 어느 곳에도 포함되면 안됨.**
- API 키 설정은, 바이너리 외부의 설정을 로드 하여야함.
  - 프로젝트 내에 포함할 수 있는 설정은 test 키만 가능함.
- 프로젝트의 멀티모듈 구조를 반드시 유지할 것.

- 테스트 코드
    - 단위 테스트, 통합 테스트 모두를 포함하여, 동작하는 테스트 코드 작성 필수.
    - 테스트 케이스들의 이름은 명확해야 하며, 이해하기 쉬워야함.

- 변경 사항을 반영시, 반드시 의미있는 branch 단위로 나누어 관리하고, main에 반영할 때는, pull request를 통할 것.
- PR 작성시엔 변경사항에 대한 자세한 설명을 작성할 것. (변경의 방향성, 선택의 사유 등)
- PR을 발행하고, 바로 병합을 해도 무방.
